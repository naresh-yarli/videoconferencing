# API Contract - Video Hosting Platform

**Version:** 1.0.0 (Based on API v1)

## Overview

This document defines the API contract for the Video Hosting Platform backend. It serves as the single source of truth for frontend developers, backend developers, QA engineers, and DevOps.

## Base URL

All API endpoints described here are relative to:

```
/api/v1
```

## Authentication

Most endpoints require authentication. The API supports:

1.  **Bearer Token Authentication (Firebase ID Token)**
    - Header: `Authorization: Bearer <firebase_id_token>`
    - Used for most user-specific operations. Token obtained via Firebase client SDKs.
    - The backend verifies this token against Firebase Auth and maps it to an internal user record.
2.  **API Key Authentication**
    - Header: `X-API-Key: <api_key>`
    - Used for programmatic access or service-to-service communication. Keys generated via user settings.

The specific authentication requirements are noted for each endpoint group or individual endpoint. Generally, user actions require a Bearer token, while some programmatic or webhook endpoints might use API keys or lack authentication.

## Common Error Responses

Endpoints may return standard HTTP error codes and formats:

- **400 Bad Request:** Invalid input data or malformed request.
  ```json
  { "detail": "Error message or validation errors" }
  ```
- **401 Unauthorized:** Missing or invalid authentication token/API key.
  ```json
  { "detail": "Invalid authentication credentials: <reason>" }
  ```
  (May include `WWW-Authenticate: Bearer` header)
- **403 Forbidden:** Authenticated user lacks permission for the action (e.g., not owner, not admin).
  ```json
  { "detail": "User does not have permission to perform this action" }
  ```
- **404 Not Found:** Requested resource (user, video, stream, etc.) does not exist.
  ```json
  { "detail": "Resource not found" }
  ```
- **422 Unprocessable Entity:** Input data failed validation (specific field errors).
  ```json
  {
    "detail": [
      {
        "loc": ["body", "field_name"],
        "msg": "Validation error message",
        "type": "validation_type"
      }
    ]
  }
  ```
- **500 Internal Server Error:** An unexpected error occurred on the server.
  ```json
  { "detail": "Internal server error message" }
  ```

## Endpoints

### Authentication (`/auth`)

Handles user authentication verification and session management.

#### 1. Verify Token & Get Custom Token

- **Endpoint:** `/auth/verify`
- **Method:** `POST`
- **Authentication:** Required (Bearer Token - Firebase ID Token)
- **Purpose:** Verify a Firebase ID token, get/create the corresponding user in the DB, and return a custom token (potentially for WebSocket or other internal uses, although JWT seems unused elsewhere). Checks for deactivated status.
- **Request:** None (Token in `Authorization` header)
- **Response (200 OK):**
  ```json
  {
    "access_token": "string", // Custom token generated by backend
    "token_type": "bearer",
    "admin": "boolean" // Whether the user has admin privileges
  }
  ```

#### 2. Get Current User Info

- **Endpoint:** `/auth/me`
- **Method:** `GET`
- **Authentication:** Required (Bearer Token - Firebase ID Token)
- **Purpose:** Retrieve profile information for the currently authenticated user based on the provided token. Updates user role based on token claims if needed.
- **Request:** None (Token in `Authorization` header)
- **Response (200 OK):**
  ```json
  {
    "id": "integer",
    "email": "string",
    "full_name": "string",
    "role": "string (USER | ADMIN)",
    "is_verified": "boolean",
    "is_active": "boolean",
    "is_admin": "boolean"
  }
  ```

#### 3. Verify Admin Status

- **Endpoint:** `/auth/verify-admin`
- **Method:** `GET`
- **Authentication:** Required (Bearer Token - Firebase ID Token)
- **Purpose:** Check if the currently authenticated user has admin privileges. Gets/creates user and updates role if necessary.
- **Request:** None (Token in `Authorization` header)
- **Response (200 OK):**
  ```json
  {
    "isAdmin": "boolean"
  }
  ```

  ```json
    "full_name": "string (optional)",
    "role": "string (USER | ADMIN, default: USER)"
  ```

  ```json
  {
    "id": "integer",
    "email": "string",
    "firebase_uid": "string",

    "is_verified": "boolean",
  ```

#### 3. Get User by ID

#### 4. Update User

#### 5. Deactivate User

- **Endpoint:** `/users/{user_id}/deactivate`

  ```json
  {
    "id": "integer",
    "title": "string",
    "description": "string (optional)",
    "owner_id": "string", // Firebase UID

    "thumbnail_type": "string (auto | custom)",

    "created_at": "string (ISO datetime)",
  ```

### WebRTC Signaling (`/webrtc`)

Handles WebRTC connection negotiation for live streaming. Base URL: `/api/v1/streams/webrtc`

#### 1. Initiate Publisher Connection

- **Endpoint:** `/webrtc/publish/{stream_id}`
- **Method:** `POST`
- **Authentication:** Required (Bearer Token - Firebase ID Token). Must be stream owner.
- **Purpose:** Initiate a WebRTC publisher connection by sending the SDP Offer.
- **Path Parameters:**
  - `stream_id`: integer
- **Request Body:**
  ```json
  {
    "offer": {
      // Or "signal"
      "type": "offer",
      "sdp": "string"
    }
  }
  ```
- **Response (200 OK):**
  ```json
  {
    "connection_id": "string",
    "stream_id": "integer",
    "success": true
    // ICE servers might be needed here depending on client config
  }
  ```

#### 2. Initiate Viewer Connection

- **Endpoint:** `/webrtc/view/{stream_id}`
- **Method:** `POST`
- **Authentication:** Optional (No explicit auth check in backend implementation for the connection itself, but expects `user_id` in body). Public streams accessible.
- **Purpose:** Initiate a WebRTC viewer connection, retrieving the publisher's Offer.
- **Path Parameters:**
  - `stream_id`: integer
- **Request Body:**
  ```json
  {
    "user_id": "string" // ID of the viewing user (could be guest ID or authenticated UID)
  }
  ```
- **Response (200 OK):**
  ```json
  {
    "connection_id": "string",
    "stream_id": "integer",
    "offer": {
      // Publisher's Offer
      "type": "offer",
      "sdp": "string"
  ```

- **Method:** `POST`

- **Purpose:** Send the viewer's SDP Answer to the backend.
- **Path Parameters:**
